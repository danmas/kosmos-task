## Философия проекта

«kosmos-task — это не инструмент. Это новый способ существования идей.»

Один исполняемый Markdown-файл (`.kosmos.md`) = полный живой проект:
- Идея → задачи → код → результат → выводы
- 100% Git-friendly, 100% читаемый человеком, 100% выполняемый AI/скриптом/человеком

## Тон общения

- Дружеский, прямой, слегка космический.
- Эмодзи используем умеренно.
- Всегда поддерживаем и ускоряем.

## Оценка сложности задач и уточняющие вопросы (обязательное правило)

**Перед тем как выполнять любую задачу:**

1. Оцени её сложность по шкале **0–7**.
2. Задай ровно **N уточняющих вопросов**, где N = оценка сложности (для 0 вопросов не задаём).
3. Получи ответы на **все** вопросы.
4. Только после этого приступай к выполнению задачи.

Это правило помогает минимизировать ошибки и переделки за счёт достаточного контекста.

### Шкала сложности (0–7)

| Уровень | Название              | Описание |
|--------|-----------------------|----------|
| **0**  | Тривиально ясно      | Всё предельно понятно. Можно сразу писать код, выполнять команды или вносить изменения. Уточнения не требуются. |
| **1**  | Очень простая        | Достаточно одного маленького уточнения (имя переменной, путь к файлу, желаемый стиль и т.п.). |
| **2**  | Простая              | Нужно 2 небольших уточнения. Задача линейная, область изменений понятна. |
| **3**  | Средняя              | Требуется понимание контекста (2–3 вопроса). Может затрагивать несколько файлов или компонентов. |
| **4**  | Выше среднего        | Нужно хорошо разобраться в текущей архитектуре. Затрагивает несколько модулей, есть нюансы взаимодействия. |
| **5**  | Сложная              | Значительные изменения. Много взаимосвязей, требуется продумать архитектуру части системы. |
| **6**  | Очень сложная        | Крупные изменения в архитектуре. Много объектов, глубокие последствия, высокая вероятность побочных эффектов. |
| **7**  | Экстремально сложная | Анализ и рефакторинг сложного проекта. Большое количество взаимосвязей, много объектов, значительный объём изменений, высокая неопределённость. Требует детального обсуждения. |

### Как оценивать сложность

- Учитывай **объём изменений** (строки кода, количество файлов).
- Учитывай **глубину** (насколько глубоко придётся лезть в существующий код).
- Учитывай **риски** и **неопределённость** (неясные требования, сложные зависимости, критичные части системы).
- Если сомневаешься — округляй **в большую сторону**.

**Примеры:**
- «Замени текст на кнопке» → 1
- «Сделай поддержку Python в executable блоках» → 5–6
- «Перепиши kosmos-runner-cli.js на TypeScript с сохранением всей текущей функциональности» → 7

## Архитектура и структура проекта

- `kosmos-runner-cli.js` — главный CLI исполнитель v2.0 (JS, использует `vm` sandbox)
- `server/` — REST API (Express + CORS)
  - `routes/` — API endpoints (/api/files, /api/execute, /api/llm)
  - `services/` — parser, executor, validator
- `src/` — TypeScript для фабрики задач и LLM интеграции
  - `task-factory.ts`, `factory.ts`, `llm.ts`, `env.ts`
- `specification/` — kosmos-spec-v1.0.json (и .yaml) — **system prompt для генерации .kosmos.md**
- `prompts/` — промпты для Task Factory (вопросы + генератор)
- `data/` — хранилище сгенерированных .kosmos.md (игнорируется git)
- `test-example.kosmos.md` — рабочий пример

**Предпочтительный рантайм:** Bun (v1+). Поддерживается Node.js 18+.

**LLM:** OpenAI-совместимый endpoint (через `.env`: `LLM_SERVER_URL`, `LLM_MODEL`, `LLM_API_KEY`). В коде есть mock fallback для демо.

## Формат .kosmos.md (строго соблюдать!)

См. полную спецификацию в `specification/kosmos-spec-v1.0.json` и `prompts/`.

Обязательная структура:
```
# Название .kosmos.md

**Статус:** in progress
**Прогресс:** 0%
**Последнее обновление:** YYYY-MM-DD

## Краткое summary (пишется в конце)

(пусто)

## Цель

[2-8 предложений]

## Задача 1: Название

### Шаг 1: Название шага
- [ ] Выполнено
 ```js executable
      console.log("...");
```
Ожидаемый результат: ...

Результат:
(пусто)

Верификация:
- [ ] пройдена.
```

**Правила генерации и редактирования:**
- НИКОГДА не нарушать структуру.
- Только чистый вывод готового файла при генерации (без пояснений).
- Все чекбоксы начинаются как `- [ ]`
- Исполняемый код только в ` ```lang executable` (пробел перед executable).
- Запрещено: fs.writeFile, mkdir, child_process в executable блоках (только чистые вычисления/логи).
- Исполняется только JS (пока). 
- После выполнения runner обновляет **Результат:**, **Верификация**, **Прогресс**, **Последнее обновление** и статус.

## Скрипты и команды

```bash
bun install

# Запуск living document
bun kosmos-runner-cli.js test-example.kosmos.md
bun kosmos-runner-cli.js project.kosmos.md --no_validate

# REST API сервер
bun run server
bun run dev          # с watch

# Task Factory (генерация .kosmos.md через вопросы → LLM)
bun run factory

# Node fallback
bun run start:node
bun run server:node
```

## Стиль кода и конвенции

- Комментарии и строки UI преимущественно на русском.
